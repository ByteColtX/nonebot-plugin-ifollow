## Responsibility

轮询子系统由四个模块组成，共同负责「发现到期作者 → 抓取 → 投递 → 记状态」。
本文件是这一个边界的唯一 spec；四个文件是实现分解，不各自建 spec。

| 模块 | 职责 |
| :--- | :--- |
| `poller.py` | 常驻循环、到期调度、抓取并发、作者级退避与停用 |
| `delivery.py` | 筛选新作品、补发上限、逐作品发送、游标推进、跨 feed 去重 |
| `failures.py` | 失败分类（作品级 / 目标级）与重试策略常量 |
| `status.py` | 运行时状态容器与 `爱播状态` 文案 |

## Boundary

- 输入：`SubscriptionStore` 快照、`PlatformAdapter`、`UniMessage`。
- 输出：发往订阅目标的消息，以及经 store 写回的游标与作者元数据。
- 不解析平台响应、不拼文案、不直接读写文件。
- 不导入 `parsehub`：作品级永久错误按异常类名判断，导入会连带加载 numpy/opencv。

## 调度

- 每个作者持有 `next_poll_at`，到期才抓取，所以轮询周期与作者数量无关；启动后立即首轮。
- 扫描间隔取周期的四分之一，夹在 15 秒到 5 分钟之间。
- 抓取阶段并发上限 4，发送阶段全局串行。
- 状态全部挂在 `Poller` 实例上（`states` / `in_flight` / `stats` / `DeliveryContext`），
  重启清零；测试不再需要清理模块级全局变量。

## 投递

- 作品在外层、目标在内层：一条作品只解析下载一次，再依次发给所有目标。
- 新作品按 `(发布时间, 作品 ID)` 全序与游标比较，`work_id` 相同直接视为已发——没有「游标作品
  被删除」「游标没有时间」这类特例。
- 每个 feed 每轮最多补发 `IFOLLOW_SUB_MAX_ITEMS` 条（默认 5）：超出时保留最新几条，更早的
  静默跳过，游标跟着推进到最新已发的那条，并记一条 warning。
- 跨 feed 去重靠「每个作者 × 每个目标」最近 50 个已发标识的环形缓冲，不再依赖本轮抓取窗口。
  必须按作者分组：`PlatformWork.identity` 只在平台内唯一，抖音 `aweme_id` 与 B 站动态 id
  都是 19 位数字，共享缓冲会把另一个作者的作品误判成已发。

## 失败处理

| 失败 | 处理 | 游标 |
| :--- | :--- | :--- |
| 作者接口暂时失败（`TransientError`） | 作者级退避 30 秒起指数增长，上限 300 秒 | 不动 |
| 作者永久失败（`PermanentError`，如作者注销） | 停用该作者，不再轮询，状态里标「已停用」 | 不动 |
| 作品已删除 / 平台不支持 | 立即放弃该作品 | 推进 |
| 网络、限流、下载失败 | 重试，连续 3 次后放弃 | 推进 |
| 目标群不可用（被踢、群解散） | 跳过该目标，本轮不再尝试 | 不动 |

- 放弃意味着这个作品不会重发；推进游标是为了不让一个坏作品卡死后续内容。
- 重试计数在失败与成功两条路径上都会清理，不会留下残余条目。
- 一个 feed 失败不影响同一作者的其他 feed；全部 feed 都失败才按作者失败处理。

## 状态

- 退订的作者和目标在每轮扫描前清掉，内存不随历史订阅增长。
- `爱播状态` 只读运行时状态，不写盘。
